# telegram-bot-service

Telegram-бот RBS. Сейчас он работает как поддержка: принимает обращения пользователей и ресторанов, пересылает их в чат поддержки и доставляет ответы обратно. Позже сюда же можно добавить уведомления о бронях.

## Как устроен

- **Long polling.** Бот сам забирает новые сообщения у Telegram (`getUpdates`), поэтому ему не нужны домен, HTTPS и открытый порт.
- **Одна реплика.** Один токен может опрашивать только один экземпляр. Если запустить второй, Telegram ответит `409 Conflict`. Не масштабируйте сервис через `--scale`.
- **Bot API** вызывается тонким клиентом на `RestClient` (`telegram/client/TelegramApiClient`) без сторонних библиотек.
- **Черновик обращения**, то есть ответы пользователя по шагам, хранится в памяти (Caffeine, 30 минут без активности). Готовые обращения и переписка хранятся в БД `telegrambotdb`.
- Все тексты бота собраны в `support/view/SupportTexts.java`, чтобы менять формулировки, не трогая логику.
- Меню команд бот регистрирует сам при старте (`setMyCommands`), в @BotFather его настраивать не нужно.

## Структура кода

Пакеты разделены по ответственности. Зависимости идут сверху вниз: `telegram` ничего не знает о боте, а `bot` не содержит логики сценариев.

```
my.project.telegrambotservice
├── config/                  настройки (app.telegram, app.support) и RestClient для Bot API
├── telegram/                Telegram Bot API — транспорт, без логики бота
│   ├── client/              TelegramApi + TelegramApiClient: вызовы методов Bot API
│   ├── dto/                 Update, Message, кнопки, запросы
│   └── polling/             UpdatePoller (long polling) и интерфейс UpdateHandler
├── bot/                     общий каркас бота
│   ├── UpdateRouter         единая точка входа: отдаёт обновление стороне пользователя или поддержки
│   ├── BotSender            отправка HTML, ответы на кнопки, реакции
│   ├── BotCommandsRegistrar меню команд при старте
│   ├── Commands             список и разбор команд
│   └── Html                 экранирование текста
└── support/                 функция «поддержка»
    ├── user/                сторона пользователя
    │   ├── UserMessageHandler   вход для сообщений: команда, ответ на шаг, дописывание или новое обращение
    │   ├── UserCommandHandler   /start, /help, /feedback, /restaurant, /cancel
    │   ├── UserCallbackHandler  кнопки: тема, «Пропустить», «Отправить», «Изменить», «Отменить», оценка
    │   ├── DraftInputHandler    проверка и сохранение ответов на шагах черновика
    │   ├── DialogNavigator      какой вопрос задать следующим
    │   └── TicketSubmitter      черновик → обращение в БД → карточка в чат поддержки
    ├── staff/               сторона поддержки
    │   ├── SupportChatPublisher пользователь → поддержка: карточка, дописывания, оценки
    │   ├── StaffReplyHandler    поддержка → пользователь: доставка ответа (Reply)
    │   └── TicketActionsHandler /tickets, повторный показ карточки, закрытие
    ├── dialog/              черновик обращения: шаги, SupportDraft, DraftStorage (память)
    ├── view/                тексты, клавиатуры и callback_data кнопок
    ├── entity/              support_tickets, support_messages
    ├── repository/
    └── service/             SupportTicketService — работа с БД и статусами
```

Новая функция (например, уведомления о бронях) добавляется отдельным пакетом рядом с `support/` со своими `view`, `service` и обработчиками. `UpdateRouter` направляет к ней нужные обновления.

## Порт

Случайный (`server.port: 0`), сервис регистрируется в Eureka. REST-эндпоинтов нет, только actuator (`/actuator/health`, `/actuator/prometheus`).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather (тот же, что у алертов Grafana) |
| `TELEGRAM_CHAT_ID` | чат поддержки: сюда приходят обращения. Это может быть личный чат с ботом или группа |
| `TELEGRAM_SUPPORT_CHAT_ID` | необязательно: отдельный чат для обращений, если алерты и обращения нужно разделить |
| `TELEGRAM_BOT_ENABLED` | `false` — сервис стартует, но Telegram не опрашивает (по умолчанию `true`) |
| `TELEGRAM_BOT_DB_HOST`, `TELEGRAM_BOT_DB_PORT` | Postgres с БД `telegrambotdb` |
| `DB_USER`, `DB_PASS`, `EUREKA_URL` | как у остальных сервисов |

> Локально и на проде нельзя одновременно использовать один и тот же токен: второй экземпляр получит 409 и будет «воровать» сообщения у первого. Когда бот заработает на проде, создайте в @BotFather отдельного тестового бота и укажите его токен в `.env.local` / `.env.infra`.

## Сценарий обращения в поддержку

### Команды

| Команда | Что делает |
|---|---|
| `/start` | приветствие и выбор темы |
| `/feedback` (или `/new`) | новое обращение: выбор темы |
| `/restaurant` | сразу обращение от ресторана |
| `/cancel` | отменить заполнение |
| `/help` | как работает поддержка |
| `/tickets` | только в чате поддержки: список открытых обращений |

### 1. Пользователь начинает

Есть три способа:

- `/start` или `/feedback`: бот показывает 4 кнопки с темами.
- `/restaurant`: тема «Вопрос от ресторана» выбирается сразу.
- **Просто пишет сообщение.** Если в нём 20 символов и больше (или есть фото), бот сохраняет его как описание и спрашивает только тему. Короткое «привет» показывает приветствие с кнопками.

Темы:

| Тема | Шаги после выбора |
|---|---|
| 🐞 Ошибка на сайте | описание → скриншоты → email → проверка |
| ❓ Вопрос о бронировании | описание → email → проверка |
| 💡 Идея или пожелание | описание → проверка |
| 🏢 Вопрос от ресторана | название и адрес → описание → email → проверка |

Каждый следующий вопрос — это первый ещё не заполненный шаг. Поэтому если описание уже есть (пользователь написал его до выбора темы или приложил фото с подписью), бот его не спрашивает.

### 2. Шаги

**Название и адрес ресторана** (только для ресторанов). Принимается текст от 5 до 500 символов.

**Описание.** Принимается текст от 5 до 3000 символов. Можно отправить фото, видео или файл с подписью: подпись станет описанием, файл — вложением. Файл без подписи сохраняется, и бот просит описать проблему текстом. На стикеры и голосовые бот просит написать текстом.

**Скриншоты** (только «Ошибка на сайте», шаг необязательный):
- можно отправить до 5 фото, видео или файлов;
- альбом из нескольких фото бот подтверждает одним сообщением;
- текст на этом шаге дописывается к описанию;
- пока файлов нет, под сообщением кнопка «Пропустить», после первого файла — «Готово».

**Email аккаунта на сайте** (необязательный шаг, нужен, чтобы найти брони или ресторан). Адрес проверяется по формату, для отказа есть кнопка «Пропустить».

**Проверка.** Бот показывает тему, ресторан, email, число вложений и описание. Под ними три кнопки:
- ✅ **Отправить**
- ✏️ **Изменить описание**: бот просит новое описание и возвращает к проверке, остальные ответы сохраняются;
- ✖️ **Отменить**.

Кнопка «Отменить» есть на каждом шаге, также работает команда `/cancel`. Если пользователь молчит 30 минут, черновик забывается.

### 3. Отправка

1. Обращение сохраняется в БД и получает номер, например **#12**.
2. В чат поддержки приходит карточка: тема, имя пользователя (ссылка на профиль), @username, email, ресторан, описание и кнопка «✅ Закрыть обращение». Вложения приходят копиями ответом на карточку.
3. Пользователь получает сообщение: «Обращение #12 принято. Мы ответим прямо в этом чате, обычно в течение дня. Если захотите что-то добавить — просто напишите сюда».

Повторное нажатие «Отправить» ничего не делает, дубля не будет.

### 4. Переписка

- **Пользователь дописывает.** Пока обращение не закрыто, любое его сообщение (текст, фото, файл, стикер) пересылается в чат поддержки с заголовком «💬 #12 · Имя». Бот ставит на сообщение реакцию 👌 вместо отдельного ответа «получено».
- **Поддержка отвечает.** Сотрудник отвечает через Reply на карточку, на любое сообщение пользователя или на свой прошлый ответ. Пользователь получает «💬 Ответ поддержки · обращение #12» и текст или файл. После доставки бот ставит на ответ сотрудника 👍.
- **Если пользователь заблокировал бота,** в чате поддержки появится «⚠️ Не доставлено».
- **Если сделать Reply на сообщение, не связанное с обращением:** в группе бот подскажет, куда отвечать. В личном чате админа такое сообщение обрабатывается как обычное пользовательское, так удобно проверять бота на себе.

Статусы обращения: `OPEN` — ждёт ответа поддержки, `ANSWERED` — поддержка ответила, ждём пользователя, `CLOSED` — закрыто. Сообщение пользователя возвращает статус `OPEN`, ответ поддержки ставит `ANSWERED`.

### 5. Закрытие и оценка

1. Сотрудник нажимает «✅ Закрыть обращение» на карточке.
2. Пользователь получает «Обращение #12 закрыто. Помогли ли мы вам?» с кнопками 👍 и 👎.
3. Оценка сохраняется в обращении и приходит в чат поддержки: «⭐ Оценка по обращению #12: 👍». При 👎 пользователю предлагается кнопка «📝 Новое обращение».
4. Если ответить на закрытое обращение, оно снова откроется.
5. После закрытия новое сообщение пользователя начинает новое обращение.

### 6. `/tickets` в чате поддержки

Показывает незакрытые обращения (до 20, самые давние первыми) со статусом и временем последнего сообщения. Под списком кнопки с номерами: нажатие присылает карточку обращения заново. На неё можно ответить через Reply, даже если исходная карточка ушла далеко вверх.

### Ограничения

- До 5 новых обращений на пользователя в сутки (`app.support.max-tickets-per-day`).
- До 5 вложений на обращение, описание до 3000 символов.
- Бот отвечает только в личных чатах. В группы его добавлять не нужно, кроме группы поддержки, если вы её заведёте.

## База данных

БД `telegrambotdb`, схема задаётся Liquibase (`db/changelog`), Hibernate работает в режиме `ddl-auto: validate`.

- `support_tickets` — обращения. Номер обращения совпадает с `id`.
- `support_messages` — переписка. По паре `(support_chat_id, support_message_id)` бот находит обращение, когда сотрудник отвечает через Reply.
