# Динамическое ценообразование в RBS

## 1. Цель

Целью данного модуля является разработка **математически обоснованного механизма динамического формирования цены бронирования** столиков в ресторанах на основе статистических данных и методов теории принятия решений.

Модуль расширяет базовую модель бронирования за счёт:
- сервисного сбора;
- динамической надбавки к цене;
- автоматического подбора оптимальной цены.

Это позволяет:
- максимизировать ожидаемую выручку;
- учитывать поведение пользователей;
- продемонстрировать применение прикладной математики и алгоритмов оптимизации в дипломной работе.

---

## 2. Общая постановка задачи

Пусть для каждого бронирования известен **контекст**:
- тип столика (VIP, у окна, обычный);
- день недели (будний / выходной / праздник);
- временной интервал (time bucket);
- ресторан.

Необходимо выбрать цену так, чтобы **ожидаемая выручка была максимальной**, при неизвестной вероятности бронирования.

Фактическая цена фиксируется **в момент создания бронирования** и не изменяется в дальнейшем.

---

## 3. Математическая модель: Contextual Multi-Armed Bandits

### 3.1 Основная идея

Задача формулируется как задача **контекстного многорукого бандита** (Contextual Multi‑Armed Bandit).

- Каждая возможная надбавка к цене — это отдельный «рычаг» (arm).
- Алгоритм выбирает надбавку, наблюдает результат (бронь или отказ), и обновляет статистику.
- Со временем стратегия сходится к оптимальной.

---

### 3.2 Пространство действий (arms)

Пусть базовая цена равна `B`.

Дискретный набор надбавок:

```
A = {0%, +5%, +10%, +15%, +20%, +30%, +40%}
```

Фактическая цена:

```
P = B * (1 + delta)
```

---

### 3.3 Контекст

Контекст `x` определяется как:

```
x = (restaurantId, tableType, dayType, timeBucket)
```

Для каждого контекста ведётся своя статистика.

---

### 3.4 Награда (reward)

Для каждого показа цены фиксируется:

- `y ∈ {0,1}` — факт бронирования;
- `p` — предложенная цена.

Функция награды:

```
r = p * y
```

Цель алгоритма — максимизировать сумму наград.

---

## 4. Алгоритм: Thompson Sampling

### 4.1 Почему Thompson Sampling

- байесовская интерпретация;
- баланс исследования и эксплуатации;
- хорошо подходит для задач динамического ценообразования;
- не требует ML‑библиотек.

---

### 4.2 Модель

Для каждой надбавки `i` храним параметры бета-распределения:

```
θ_i ~ Beta(α_i, β_i)
```

Интерпретация:
- `α_i` — количество успешных бронирований;
- `β_i` — количество отказов.

---

### 4.3 Выбор цены

Для каждого рычага:

```
θ̂_i ~ Beta(α_i, β_i)
```

Выбирается рычаг:

```
i* = argmax (θ̂_i * p_i)
```

Где `p_i` — цена с соответствующей надбавкой.

---

### 4.4 Обновление статистики

После результата:

- если бронь создана:
```
α_i = α_i + 1
```

- если отказ:
```
β_i = β_i + 1
```

---

## 5. Связь с теорией принятия решений

Задача формулируется как **максимизация ожидаемой полезности**:

```
E[U(p)] = p * Pr(booking | p, x)
```

Где вероятность неизвестна и оценивается в процессе обучения.

Thompson Sampling реализует байесовский подход к принятию решений в условиях неопределённости.

---

## 6. Игровая интерпретация (теория игр)

Модель может быть интерпретирована как **игра Штакельберга**:

- платформа — лидер, выбирающий цену;
- клиенты — фолловеры, принимающие решение о бронировании.

Полезность клиента:

```
U = V(x) - p
```

Бронирование происходит, если `U ≥ 0`.

Алгоритм динамического ценообразования приближает оптимальную стратегию лидера по наблюдаемым реакциям фолловеров.

## 7. Архитектура в рамках RBS

### 7.1 Где живёт логика

На этапе MVP:
- pricing-логика реализуется в `booking-service`.

В перспективе:
- возможно выделение отдельного `pricing-service`.

---

### 7.2 Событийная модель

Kafka события:

- `quote.shown` — цена показана пользователю;
- `booking.created` — бронь создана;
- `booking.cancelled` — бронь отменена.

Используются для обновления статистики алгоритма.

---

## 8. Хранение статистики


Также возможно кэширование текущих параметров в Redis.
